# 정면 작업자·네 보기 판단 화면 명세

여섯 절차의 질문과 네 보기는 그대로 유지하고, 선택 화면에서 작업자가 정면으로 시선을 두며 판단을 기다리는 구도를 만든다. 실제 정면 이미지·접지·카메라·작은 대기 동작은 현장 담당이 표현한다. UI는 왼쪽 화면 약 28%의 작업자 얼굴과 몸을 가리지 않으며 오른쪽 약 48%, 최대 600px 안내판에 질문과 네 보기를 세로로 배치한다. 한 번의 판단에 집중하도록 ‘당신의 판단을 기다립니다.’를 조용하게 표시한다. 시간 제한·재촉·죄책감 표현은 없다.

배치 개념:

```text
[정면작업자 · 시선28%] | [질문 / A / B / C / D · 오른쪽48%]
```

강철 #172129, 흑연 #27333a, 밝은 회색 #e6ebed, 안전 황색 #f4d27a, 문자 #f2ede3와 한국어 시스템 고딕을 유지한다. 질문 22px·보기 16px, 큰 글씨는 질문 25px·보기 18px다. 버튼 최소 높이48px, 선택 중 1–4 키를 유지한다. 1280×720에서는 네 보기를 한 열로 읽고, 1024×576 큰 글씨에서는 안내판 내부의 보기 영역만 스크롤하여 네 선택 모두 접근한다. 질문과 화면 닫기·조작 안내는 패널 안에 유지한다.

`setChoiceFocus(true)`는 quiz dialog가 열린 뒤에만 호출한다. 선택 시작·강제 닫기·현장 보기·Escape·공장 이동·재시작에서 즉시 false로 복귀한다. 늦게 도착한 close 이벤트는 새로 열린 dialog를 해제하지 않도록 기존 open 검사를 유지한다. checkpoint snapshot은 현장 API가 선택 전 카메라를 반환하므로 선택 기록과 되감기 기준을 바꾸지 않는다. 정답·오답·완료·교육 화면은 현재 레이아웃과 행동 상태를 유지한다.

현장의 choiceFocused/displayFacing/choiceZoom/choiceScale/frontRenderedHeight/waitingMotion을 기존 위치 관찰 데이터에 전달한다. 신규 choice-focus.mjs만 정적 서버의 공개 모듈 허용 목록에 추가한다. 자동 검사는 기존 규칙·이동·서버·학습·행동·짧은 안내와 현장 helper 경계를 확인한다. 실제 여섯 질문·얼굴 가림·현장 복귀·작은 화면과 큰 글씨는 주 담당자 브라우저 QA로 확정한다. 커밋·푸시·새 의존성 설치는 하지 않는다.
