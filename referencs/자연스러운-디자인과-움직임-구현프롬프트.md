# 어떤 요인이 자연스러움을 높였나

반복하면서 좋아진 핵심 이유는 이미지, 이동, 보행, 카메라가 서로 맞도록 조정됐기 때문이다. 처음에는 각각 그럴듯해도, 함께 움직일 때 생기는 어긋남이 있었다.

| 요인 | 현재 구현에서 한 조정 | 자연스럽게 느껴지는 이유 |
|---|---|---|
| 이미지의 일관성 | 배경·인물의 따뜻한 색조와 산업현장 재질을 맞춤 | 인물이 배경에 붙여 넣은 것처럼 보이는 느낌을 줄임 |
| 중복 요소 제거 | 배경에 있던 동료를 제거하고 별도 인물로 배치 | 같은 사람이 중복되거나 겹치는 문제를 줄임 |
| 공간의 깊이 | 배경·인물·전경 난간을 분리하고 시차(Parallax)를 적용 | 이동할 때 가까운 것과 먼 것의 거리감이 생김 |
| 이동의 시작·정지 | 즉시 속도를 바꾸던 동작에 가속·감속을 적용 | 출발과 멈춤이 갑작스럽지 않으면서 입력에 반응함 |
| 방향 전환 | 먼저 감속해 멈춘 다음 방향을 바꿈 | 이동 중 몸만 순간적으로 뒤집히는 느낌을 줄임 |
| 보행과 이동의 연결 | 실제 이동 거리에 따라 걷기 자세를 선택 | 이동 속도와 다리 움직임이 따로 노는 문제를 줄임 |
| 인물의 기준점 | 자세별 발 위치·몸 높이와 좌우 반전 기준점을 보정 | 자세가 바뀔 때 인물이 위아래로 튀거나 옆으로 밀리는 느낌을 줄임 |
| 카메라 | 시간에 따른 부드러운 추적과 진행 방향의 여유 공간 적용 | 화면이 캐릭터 움직임을 따라 읽기 쉬워짐 |
| 주변의 작은 움직임 | 동료의 호흡·고개, 환기팬, 느린 먼지·빛 변화 | 정적인 사진 배경에 생활감이 생김 |
| 예외 상황 처리 | 경계에서 제자리걸음 중지, 조사창 중 이동 잠금, 재시작 초기화 | 사용자가 조작할 때 예상과 다른 움직임이 줄어듦 |

디자인 항목은 현재 합성 구조에서 자연스러움에 기여하는 요인이다. 각 수정의 기여도를 따로 측정한 결과는 아니다.

**움직임에서 실제 개선이 확인된 것은 조작과 상태 전환이다.** 과거 검사에서 출발·정지·반전·경계·조사창 잠금은 통과했다. 하지만 기존 보행 이미지는 발 미끄러짐과 자세 전환 문제로 기준에 미달했다. 따라서 “이전보다 좋아졌다”와 “자연스러운 보행이 완성됐다”는 구분해야 한다.

근거: [코드 개선 검증 기록](../테스트게임/.omo/evidence/t3-code-candidate-verification.md). 이 링크는 원본 작업 폴더를 함께 보관한 로컬 환경에서 확인할 수 있다. 참고팩만 공유할 때는 [기존 구현의 현재 상태](02-참고자료/현재상태.md)를 확인한다.

## 처음부터 요청할 때 중요한 것

“자연스럽게 만들어줘”에 다음 세 가지를 붙이는 것이 좋다.

- **무엇이 일치해야 하는가:** 광원·인물 크기·바닥 접촉·이동 거리·보행·카메라.
- **어떤 상황에서 확인하는가:** 출발·정지·반전·경계·조사창·재진입.
- **부족하면 무엇을 해야 하는가:** 코드 보정과 이미지 부족을 구분하고, 없는 동작을 효과로 숨기지 않기.

특히 **걷기 이미지를 준비할 때부터 발 접촉과 연속성을 요구해야 한다.** 서로 다른 자세 몇 장만 있으면 코드로 보정할 수 있는 범위가 제한된다.

## 그대로 사용할 초기 구현 프롬프트

```text
실사풍 이미지 기반의 브라우저 산업안전 게임을 구현해줘.

[목표와 범위]
- 첫 화면은 전체 공장뷰다.
- 공장의 컨베이어 구역을 클릭하면 현장 장면으로 들어간다.
- 시나리오는 하나다.
- 현장에서 이동·조사·판단·결과·다시 연습까지 연결한다.
- Phaser, HTML, CSS, JavaScript를 사용한다.
- Blender와 Three.js는 사용하지 않는다.
- 기존 구현은 참고자료다. 새 코드는 별도 작업 폴더에서 만든다.
- 이미지는 내가 제공한다. 새 이미지 폴더는 제공 전까지 비워 둔다.
- 이미지가 없으면 임시 도형으로 전체 흐름부터 연결한다.

[디자인의 일관성]
- 공장뷰와 현장은 같은 장소·시간대·재질로 느껴져야 한다.
- 회색 철골과 콘크리트, 절제된 노란 안전시설,
  따뜻한 햇빛과 저채도 그림자를 기본 방향으로 삼는다.
- 배경·인물·전경의 원근, 크기, 광원 방향, 색온도를 맞춘다.
- 이미지 비율을 보존하고 인물을 임의로 늘이거나 압축하지 않는다.
- 배경에 이미 있는 사람·난간·설비를 별도 이미지로 중복 배치하지 않는다.
- 바닥, 인물, 그림자, 전경의 앞뒤 순서를 확인한다.
- 생성 이미지에 버튼·라벨·가짜 글자를 넣지 않는다.
- 배경에 이미 포함된 빛·먼지 효과를 코드에서 중복 적용하지 않는다.
- 공장뷰의 클릭 영역은 실제로 보이는 설비 위치와 일치시킨다.

[이동]
- 이동량은 실제 경과 시간으로 계산한다.
- 가속·감속은 짧고 조작 반응은 명확하게 한다.
- 반대 방향 입력에서는 감속 후 방향을 전환한다.
- 입력 방향과 실제 이동 방향이 어긋나는 시간을 최소화한다.
- 경계에 도달하면 실제 이동과 보행 재생을 멈춘다.
- 조사창·결과창에서는 이동하지 않는다.
- 창 비활성화와 재시작 때 입력·속도를 초기화한다.
- 속도와 가감속 수치는 화면 크기와 인물 비율에 맞춰 보정한다.

[보행 이미지와 애니메이션]
- 애니메이션은 실제 이동 거리와 제작 보폭에 연결한다.
- 멈춰 있는데 걷거나, 이동하는데 발이 계속 미끄러지지 않게 한다.
- 자세마다 같은 인물·복장·체형·광원·카메라를 유지한다.
- 프레임별 신체 높이와 발 기준점을 맞춘다.
- 좌우 반전 때 비중앙 기준점도 함께 보정한다.
- 출발·정지·반전에서 지지발이 갑자기 다른 위치로 옮겨지지 않게 한다.
- 정지 자세와 보행 자세 사이의 연결도 확인한다.
- 프레임 수를 늘렸다는 이유만으로 자연스러워졌다고 판단하지 않는다.
- 제공 이미지에 완전한 보행 주기나 전이 자세가 없으면
  코드로 해결할 수 있는 범위와 추가로 필요한 이미지를 알려준다.
- 부족한 이미지로 연속 동작이 완성됐다고 보고하지 않는다.

[카메라와 주변 움직임]
- 카메라는 시간 기준으로 부드럽게 추적한다.
- 진행 방향에 적당한 여유 공간을 둔다.
- 반전·조사·복귀 때 카메라 목표가 갑자기 튀지 않게 한다.
- 인물 기준점의 흔들림은 원인을 고친 뒤 카메라를 조정한다.
- 전경 시차는 원근과 실제 겹침이 맞는 범위에서만 적용한다.
- 호흡·환기팬·먼지 등은 작고 느리게 표현한다.
- 점검 중 정지해야 하는 설비는 시나리오에 맞게 정지시킨다.
- 움직임 줄이기 설정을 지원한다.

[구현 순서]
1. 임시 도형으로 공장부터 결과까지 한 판을 연결한다.
2. 제공 이미지의 비율·광원·중복 요소·바닥·기준점을 확인한다.
3. 정지 화면에서 배경·인물·그림자·전경을 맞춘다.
4. 출발·정지·반전·경계 동작을 맞춘다.
5. 보행과 이동 거리를 맞춘다.
6. 카메라를 조정한다.
7. 필요한 주변 효과를 추가한다.

[검증]
같은 화면 크기와 같은 입력으로 다음 구간을 확인한다.
- 좌우 이동
- 짧게 눌렀다 놓기
- 이동 중 반대 방향 입력
- 양 끝 경계에서 키 유지
- 조사창을 연 채 이동 입력
- 공장 복귀와 현장 재진입
- 다시 연습
- 창 비활성화 후 복귀

입력 반응, 발 접촉, 자세 전환, 카메라 움직임을 각각 확인한다.
필요하면 인물과 바닥선만 보이는 진단 화면에서 원인을 찾는다.

초기 임시 목표:
- 출발·정지·반전의 조작 반응은 100ms 이내를 목표로 한다.
- 접지 중 발 미끄러짐은 부츠 길이의 10% 이하를 목표로 한다.
- 발과 바닥의 간격·침범은 신체 높이의 1% 이하를 목표로 한다.
이 수치는 프로젝트의 임시 기준이며 실제 화면에서 조정한다.
관찰할 수 없는 발은 측정 불가로 기록한다.

변경 전후를 같은 구간으로 비교하고,
실제로 개선된 것·남은 문제·실행하지 못한 검사를 구분해 보고한다.
코드 문제, 이미지 문제, 장면 합성 문제를 구분해 필요한 부분만 수정한다.
```

## 분석 범위와 남은 한계

이번 정리는 코드와 기존 기록을 분석했으며 새 영상 비교는 하지 않았다. 이 프롬프트를 적용해도 제공되는 보행 이미지의 연속성이 부족하면 추가 자산이 필요하다.
