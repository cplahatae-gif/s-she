# SAFEPLAY 「마지막 자물쇠」 제품 요구사항 문서

작성일: 2026-10-09
상태: 사용자 승인 명세의 T1~T7 구현 완료. 검증 기록은 ../qa/검증.md 참조.
작성 방식: to-spec 스킬에 따라 대화의 합의 내용을 정리했다.

## 1. 문제 정의

레미콘 공장에서 컨베이어 점검구 안 이물질을 제거하는 작업자는 설비가 멈춰 있다는 표시만으로 작업에 들어가서는 안 된다. 작업자는 직접 차단 지점까지 이동해 에너지를 차단하고, 본인 자물쇠와 표지를 체결하며, 잔류 에너지 안전조치와 차단 확인을 완료해야 한다.

기존 기획은 조작반 운전원이 동료의 자물쇠를 확인하고 재가동 여부를 판단하는 흐름이었다. 새 게임은 이물질 제거 작업자의 관점에서 작업 전 안전 확보를 체험하게 해야 한다.

현재 저장소에는 공장 전경의 구역 선택 화면 일부, 시나리오 원고, 인물 및 장면 이미지, Phaser가 있다. 직접 이동, 안전조치 수행, 판정, 사고 재현, 되감기, 결과까지 연결된 게임은 아직 없다.

## 2. 해결 방식

플레이어는 전체 공장 전경에서 벨트 컨베이어(B/C) 구역을 선택한다. 현장에 들어가면 점검구 밖의 안전한 위치에서 작업 요청을 받는다. 이후 작업자를 좌우로 직접 이동시키고, 가까운 대상의 조사 또는 확대 화면을 통해 실제 행동을 수행한다.

기본 흐름은 작업 대상 확인 → 차단 지점으로 이동 → 에너지 차단 → 본인 자물쇠·표지 체결 → 잔류 에너지 안전조치 → 차단 확인 → 점검구로 복귀 → 작업 진입 판단이다.

실제 차단 또는 잠금이 불완전한 상태로 작업에 들어가면 컨베이어가 불시에 움직이는 사고를 재현한다. 부상 장면은 보여 주지 않고 암전과 사고 카드 후 되감기 기회를 제공한다. 필요한 조치를 모두 완료하면 안전한 이물질 제거와 결과 화면으로 이어진다.

외부 AI(인공지능) 연결 없이 코드가 판정하고 고정 설명을 제공한다. 현장의 상세 절차가 미확정이므로 게임용 예시 설비로 구현하며, 실제 교육용 확정 전에는 현장 설비 절차와 대조한다.

## 3. 사용자 이야기

1. 플레이어로서 전체 공장 전경을 먼저 보고 싶다. 작업할 컨베이어가 공장 어디에 있는지 이해하기 위해서다.
2. 플레이어로서 컨베이어 구역을 마우스 또는 키보드로 선택하고 싶다. 현장에 들어갈 수 있기 위해서다.
3. 플레이어로서 작업 요청을 읽고 싶다. 내 역할이 이물질 제거 작업자임을 이해하기 위해서다.
4. 플레이어로서 점검구 밖에서 시작하고 싶다. 안전조치 전에는 작업 구역에 들어가지 않는 흐름을 경험하기 위해서다.
5. 플레이어로서 한국인 작업자를 직접 좌우로 움직이고 싶다. 잠금 지점까지 찾아가는 과정을 경험하기 위해서다.
6. 플레이어로서 화면 밖의 현장으로 이동하고 싶다. 작업 장소와 차단 지점 사이의 거리를 경험하기 위해서다.
7. 플레이어로서 가까이 있는 대상과 가능한 행동을 알고 싶다. 어떤 위치에서 조사·조작할 수 있는지 이해하기 위해서다.
8. 플레이어로서 점검구를 조사하고 싶다. 이물질 제거 대상과 작업 진입 위치를 확인하기 위해서다.
9. 플레이어로서 조작반의 정지 상태를 확인하고 싶다. 정지 표시와 에너지 차단이 다름을 이해하기 위해서다.
10. 플레이어로서 작업 대상에 맞는 차단 지점을 확인하고 싶다. 다른 설비나 단순 정지 버튼을 차단으로 오인하지 않기 위해서다.
11. 플레이어로서 실제 차단 행동을 수행하고 싶다. 설명창을 읽는 것만으로 완료되지 않는 안전조치를 경험하기 위해서다.
12. 플레이어로서 본인 자물쇠를 올바른 위치에 체결하고 싶다. 차단 상태를 유지하는 행동을 경험하기 위해서다.
13. 플레이어로서 잘못된 잠금 위치도 선택해 보고 싶다. 자물쇠가 보이는 것과 실제 차단 장치가 잠긴 상태의 차이를 이해하기 위해서다.
14. 플레이어로서 본인 표지를 별도로 부착하고 싶다. 자물쇠 체결과 표지 부착이 각각 필요한 조치임을 이해하기 위해서다.
15. 플레이어로서 필요한 잔류 에너지 안전조치를 수행하고 싶다. 전원 차단만으로 작업 준비가 끝나지 않음을 이해하기 위해서다.
16. 플레이어로서 차단 확인 행동과 그 결과를 보고 싶다. 설명을 읽는 것과 차단을 확인하는 행동을 구분하기 위해서다.
17. 플레이어로서 차단 확인에서 이상이 발견되면 보완하고 다시 확인하고 싶다. 실패를 발견한 뒤 작업을 보류하는 과정을 경험하기 위해서다.
18. 플레이어로서 완료한 안전조치와 빠진 조치를 구분해 보고 싶다. 현재 작업 진입이 가능한지 판단하기 위해서다.
19. 플레이어로서 점검구에서 작업 진입 또는 안전조치 보완을 선택하고 싶다. 내 행동 상태를 근거로 결정하기 위해서다.
20. 플레이어로서 위험한 상태로 진입했을 때 사고 재현과 고정 이유를 보고 싶다. 빠뜨린 조치와 불시 가동의 관계를 이해하기 위해서다.
21. 플레이어로서 사고 후 기록을 유지한 채 되감고 싶다. 처음부터 설명을 반복하지 않고 잘못된 조치를 바로잡기 위해서다.
22. 플레이어로서 안전조치가 실제로 모두 완료됐을 때 이물질 제거를 보고 싶다. 안전하게 준비한 행동의 결과를 확인하기 위해서다.
23. 플레이어로서 결과에서 완료한 조치, 판단 시도, 되감기 횟수를 보고 싶다. 나의 선택을 되짚기 위해서다.
24. 플레이어로서 공장으로 돌아갔다가 이어서 하고 싶다. 작업 위치와 기록을 잃지 않기 위해서다.
25. 플레이어로서 다시 연습하면 새 판으로 시작하고 싶다. 이전 완료 상태의 도움 없이 다시 수행하기 위해서다.
26. 플레이어로서 마우스를 쓰지 않고도 메뉴와 패널을 조작하고 싶다. 키보드만으로 한 판을 완료하기 위해서다.
27. 플레이어로서 움직임 줄이기 설정에서도 사고와 되감기를 경험하고 싶다. 점멸이나 흔들림 없이 내용을 확인하기 위해서다.
28. 협업자로서 별도 구현을 기존 프로젝트와 구분해 실행하고 싶다. 공용 작업을 덮어쓰지 않고 나중에 합치기 위해서다.

## 4. 구현 결정

### 4.1 범위와 실행 방식

- 사용자가 지정한 하태준 독립 구현 영역에서만 새 게임과 그 문서를 만든다. 기존 공용 게임 코드와 상대 담당 코드를 수정하지 않는다.
- 기존 폴더 구조의 역할을 따라 앱 연결, 공장뷰, 현장, 시나리오 규칙, 패널, 문서, 검사를 나눈다.
- 저장소의 공용 이미지와 Phaser를 상대 경로로 참조한다. 독립 구현 폴더만 저장소 밖으로 복사해 실행하는 배포 형태는 이번 범위에 포함하지 않는다.
- 기존 Phaser와 라이선스를 사용한다. HTML, CSS, 자바스크립트 ES 모듈(ES modules)로 만들며 프레임워크나 의존성을 새로 추가하지 않는다.
- PC 브라우저 기준으로 방향키 또는 A/D 이동, E 상호작용, 마우스·키보드 패널 조작을 제공한다.
- 한 시나리오를 끝까지 완성한다. 외부 AI, 무전 압박, 작업 후 재가동은 이번 범위에서 제외한다.

### 4.2 화면 흐름

| 화면 | 플레이어 행동 | 결과 |
|---|---|---|
| 공장 전경 | B/C 구역 클릭 또는 키보드 선택 | 현장과 작업 요청 표시 |
| 현장 탐색 | 이동, 가까운 대상 조사 | 조사 기록과 대상별 확대 화면 |
| 차단·잠금 확대 | 차단, 본인 자물쇠, 표지 행동 | 실제 안전조치 상태 갱신 |
| 안전조치·차단 확인 | 잔류 에너지 조치 및 차단 확인 수행 | 완료 또는 이상 발견, 보완 안내 |
| 점검구 진입 판단 | 안전조치 보완 / 현재 상태로 진입 | 탐색 / 미완료 / 사고 / 성공 |
| 사고 재현 | 연출 후 되감기 선택 | 진입 전 안전한 위치로 복귀 |
| 안전한 작업·결과 | 이물질 제거 확인, 기록 확인 | 다시 연습 또는 공장 복귀 |

점검구, 조작반, 차단·잠금 지점, 확인 행동 지점은 역할을 구분한다. 원거리에서는 조작할 수 없으며, 유효한 상호작용은 현장의 거리 검사 후 요청된다. 확대 화면은 조사 내용을 읽는 기능과 실제 행동 버튼을 구분한다.

카메라는 이동하는 작업자를 따라가고 월드 경계를 넘지 않는다. 배경의 비율을 유지하며, 화면보다 넓은 현장과 연속된 보행 경로를 구성한다. 구체적인 배치 수치와 조사 거리는 구현 시 자산 크기에 맞춰 정하되 한 곳에서 관리한다.

### 4.3 한 판의 상태와 모듈 경계

- 앱 연결 모듈이 한 판의 상태와 화면 상태를 소유한다. 현장과 패널은 콜백으로 행동을 요청한다.
- 시나리오 규칙 모듈은 DOM(문서 객체 모델), Phaser, 통신 없이 행동의 유효성과 진입 판정을 계산한다.
- 조사 기록은 집합(Set)으로 중복을 방지한다. 조사 기록과 실제 안전조치 상태는 별개다.
- 실제 상태는 에너지 차단, 본인 잠금의 유효성, 표지 부착, 잔류 에너지 조치, 차단 확인 결과를 구분한다.
- 정지 표시 확인은 에너지 차단 상태를 완료시키지 않는다.
- 단순히 자물쇠가 표시되거나 잠금 지점을 조사한 것만으로 잠금을 완료시키지 않는다.
- 잘못된 잠금 위치는 유효한 개인 잠금으로 판정하지 않는다. 실패를 발견하고 올바른 위치로 보완할 수 있다.
- 차단 확인은 행동을 수행한 뒤 결과가 나타나야 한다. 확인이 실패한 상태는 성공 조건을 충족하지 못한다.
- 차단 대상·잠금·잔류 에너지 상태를 변경하면 이전 확인 결과는 무효가 되어 다시 확인해야 한다.
- 잘못된 식별자·자료형·현 단계에서 허용되지 않은 행동은 거절하며, 완료 상태나 진입 시도 횟수를 임의로 갱신하지 않는다.
- 기존 운전원용 조사·선택 식별자를 새 의미로 조용히 재사용하지 않는다. 새 인터페이스(Interface)는 독립 구현의 문서에서 정하고, 공용 계약 변경은 추후 합치는 작업에서 별도로 한다.

### 4.4 진입 판정

판정은 플레이어의 실제 행동 상태로 결정하며, 무작위 사고를 넣지 않는다.

| 진입 요청 상태 | 결과 | 고정 이유 |
|---|---|---|
| 실제 에너지 차단 미완료 | 사고 재현 | 정지 표시는 에너지 차단과 잠금의 확인을 대신하지 못한다 |
| 실제 차단을 유지할 본인 잠금이 없거나 잘못 체결됨 | 사고 재현 | 자물쇠가 보이는 것만으로 차단 상태가 유지되지 않는다 |
| 차단·잠금은 유효하지만 표지·잔류 에너지 조치·확인이 미완료 | 미완료 안내 | 빠진 필수 조치를 완료한 뒤 진입해야 한다 |
| 차단 확인에서 이상 발견 | 작업 보류와 보완 안내 | 차단이 확인되지 않아 작업에 들어갈 수 없다 |
| 모든 필수 안전조치 및 차단 확인 완료 | 성공 | 직접 차단·본인 잠금·표지·안전조치·확인을 마치고 작업에 들어간다 |

이 초안의 사고 원인은 실제 에너지 차단 또는 잠금 실패로 한정한다. 표지 누락이나 확인 생략 자체가 벨트를 움직이게 한다고 묘사하지 않는다. 잔류 에너지의 구체적 위험을 추가하는 것은 실제 설비 자료 확인 후 별도 결정한다.

유효한 작업 진입 제출 한 번에 판정은 한 번만 실행되고, 판단 시도 횟수도 한 번만 증가한다. 안전조치 보완 선택과 조사·잠금 행동은 판단 시도에 포함하지 않는다.

### 4.5 사고, 기록 유지, 초기화

- 불완전한 차단 상태로 점검구 작업에 들어간 뒤 사고를 재현한다. 잠금장치 앞에서 즉시 사고가 나지 않는다.
- 기본 연출은 붉은 점멸, 짧은 흔들림 또는 벨트 움직임, 암전, 사고 카드 순서다. 연출은 6초 이내에 끝나며 부상자·피·피해자 실명을 보여 주지 않는다.
- 움직임 줄이기에서는 점멸·흔들림 없이 붉은 고정 레이어, 암전, 사고 카드로 완주한다.
- 사고 카드는 임의로 닫을 수 없고 되감기 버튼으로 현장에 돌아간다.
- 되감기는 진입 전 안전한 위치로 돌아가며 횟수만 하나 늘린다. 조사, 판단 시도, 사고 전 안전조치를 유지하고 실패한 조치를 보완할 수 있게 한다.
- 되감기는 안전조치를 자동 완료시키지 않는다.
- 공장 복귀와 재진입은 기록·안전조치·작업자 위치를 유지한다. 공장에 있는 동안 현장 입력과 연출은 정지한다.
- 다시 연습은 조사·안전조치·판단 시도·되감기·위치·입력·카메라·패널·연출 타이머를 초기화한다.
- 패널·결과·공장 화면에서는 이동하지 않는다. 창이 비활성화되면 눌린 키와 속도를 초기화한다.
- 이벤트와 타이머는 재진입 때 중복되지 않도록 해제한다. 처리 중에는 반복 제출을 막는다.

### 4.6 이미지와 화면 표현

- 기존 주요 장면과 동일한 40대 한국인 작업자를 유지한다.
- 전체 공장 전경은 기존 공용 공장 이미지를 사용한다. 현장 시작 구도는 점검구 앞 출발안을 기본으로 잡고, 기존 다른 후보는 비교 자료로 남긴다.
- 사진에 가까운 산업시설 스타일을 유지한다. 회색 철골, 검은 고무 벨트, 회갈색 골재·콘크리트, 황토빛 노란 난간, 가벼운 녹·마모·먼지를 사용한다.
- 오른쪽 뒤의 따뜻한 낮은 오후 햇빛과 차가운 실내 그림자를 유지한다. 사람과 설비의 크기는 현실적이어야 한다.
- 이동용 배경은 기존 장면에서 인물을 제거해 준비한다. 인물은 투명 배경으로 분리하고 별도의 보행 동작을 준비한다.
- 인물이 합쳐진 장면 위에 이동 인물을 추가하지 않는다. 캐릭터 시트의 정지 자세를 보행 이미지로 간주하지 않는다.
- 보행은 이동 거리와 발 접촉을 맞추고, 정지·방향 전환·경계를 확인한다.
- 기존 주요 장면 사진은 확대 화면, 안전한 작업 및 결과 연출에 활용할 수 있다.
- 새 이미지 자체에는 제목·버튼·로고·워터마크·커서·번호·읽을 수 있는 글자·가짜 글자를 넣지 않는다. 안내와 조작은 접근 가능한 화면 요소로 별도 표시한다.
- 이미지 파일이 없거나 로딩되지 않으면 성공 상태를 꾸미지 않는다. 오류를 안내하고 다시 로딩할 수 있도록 한다.

### 4.7 접근성과 안내

- 공장 선택, 확대 화면, 진입 판단, 결과는 키보드로 조작할 수 있어야 한다.
- 패널에는 제목과 읽기 순서가 있고, 열 때 포커스(Focus)를 안으로 이동한다. 닫으면 관련 조작 위치로 복원한다.
- 색상만으로 완료·미완료를 구분하지 않고 문자와 상태 표시를 함께 제공한다.
- 현재 목표, 상호작용 가능 대상, 완료한 조치와 빠진 조치를 보여 준다.
- 진행 안내가 필요한 행동을 대신 수행하지 않는다. 성공은 실제 완료 상태로 판정한다.
- 고정 설명을 사용하며, 외부 AI 실패처럼 보이는 안내를 상시 표시하지 않는다.
- 게임용 예시 설비임을 작업 안내에 짧게 표시한다. 실제 현장에 없는 세부 절차를 사실로 확정하지 않는다.

## 5. 검사 결정

### 5.1 검사 경계

검사 지점은 두 가지로 제한한다.

1. 한 판 규칙의 공개 행동 요청과 판정 결과: 유효한 행동과 잘못된 행동을 입력하고, 사용자에게 의미 있는 완료 상태·결과·기록을 확인한다.
2. 브라우저에서의 사용자 흐름: 실제 키·클릭을 사용해 공장 진입, 이동, 확대 조작, 판단, 사고·성공·복귀·재연습을 확인한다.

내부 변수명, 함수 호출 횟수의 구현 방식, 화면 구성 순서 자체를 고정하는 검사는 피한다. 유효한 진입 제출당 기록이 한 번만 증가하는 등 외부에서 관찰할 수 있는 계약은 검사한다.

기존 저장소에는 실행 가능한 시나리오 검사나 완성된 현장이 없다. 새로운 독립 구현의 규칙 검사와 브라우저 검증을 준비한다. 공장 선택의 기존 화면을 참고하되 검사 통과를 이미 확보한 것으로 간주하지 않는다.

### 5.2 완료 기준

- 공장 전경에서 마우스와 키보드로 컨베이어에 진입한다.
- 이동·정지·반전·경계·카메라와 대상별 거리 제한이 동작한다.
- 조사만으로 안전조치가 완료되지 않는다.
- 실제 차단 생략과 잘못된 잠금 후 진입은 사고 재현으로 이어진다.
- 차단·잠금이 유효한 상태의 표지·잔류 에너지 조치·확인 누락은 미완료로 처리한다.
- 차단 확인에서 이상을 발견하고 보완한 뒤 다시 확인할 수 있다.
- 모든 필수 조치 후 진입하면 이물질 제거와 결과 화면에 도달한다.
- 반복 입력으로 판정·기록·연출이 중복되지 않는다.
- 되감기 이후 기록과 안전조치가 유지되며, 되감기로 빠진 조치가 채워지지 않는다.
- 공장 복귀 후 이어하기는 위치와 상태를 유지한다.
- 다시 연습은 새 판과 동일한 초기 상태로 돌아간다.
- 패널과 창 비활성화 중 이동이 멈추고, 닫은 뒤 입력이 달라붙지 않는다.
- 움직임 줄이기에서도 사고 카드와 되감기에 도달한다.
- 키보드만으로 한 판을 완료하고, 패널 종료 뒤 포커스가 복원된다.
- 대표 화면과 보행의 화면 캡처로 인물 중복·가림·발 접촉·문구 읽힘을 확인한다.
- 원본 공용 코드와 자산을 수정하지 않고 독립 구현의 주소에서 실행된다.

## 6. 제외 범위

외부 AI·서버 연결, 로그인·성적 저장, 추가 시나리오, 무전 압박·시간 제한, 작업 후 자물쇠 해제·재가동 절차, 휴대폰 전용 조작, 3D·Blender·Three.js, 라이브러리 교체, 공용 코드와의 실제 병합, 현장 설비 절차 승인, GitHub 이슈 등록은 이번 구현에 포함하지 않는다.

## 7. 추가 메모

### 확인된 합의

사용자는 직접 이동과 확대 화면 조작, 고정 설명, 공용 자산 참조, 이동용 이미지 추가 제작, 게임용 예시 설비, PC 조작을 추천안대로 승인했다. 이후 게임 구현을 중단하고 PRD부터 작성하도록 지시했다.

사용자가 implement-spec으로 구현을 요청해 검사 경계와 티켓 분할을 승인했다. 작업 추적은 사용자 지정 독립 폴더 안의 로컬 문서로 관리한다. 외부 이슈 추적기(Issue tracker)에 게시하지 않았다.
