# 디자인과 움직임 개선 기록

검증일: 2026-10-09. 기준: 참조 폴더의 자연스러운 디자인과 움직임 구현 프롬프트. 수정 범위는 하태준 독립 구현이다.

## 사용한 스킬

- `video-frame-analysis`: 브라우저 녹화를 프레임으로 추출하고 연속 장면을 확인했다. 제공 스크립트의 시간 표시 필터가 Windows FFmpeg에서 충돌해, 시간 표시를 뺀 FFmpeg 추출과 위치·카메라 기록으로 대체했다. 문자 인식(OCR)과 음성 전사는 이번 동작 분석에 사용하지 않았다.
- `camera-systems`: 시간 기반 추적, 진행 방향 여유 공간, 작은 움직임을 무시하는 영역, 양쪽 경계 처리를 적용했다.
- `game-studio:game-playtest`: 실제 키·클릭과 화면 캡처로 이동과 게임 흐름을 확인했다.

## 관찰과 수정

| 관찰 | 반영한 수정 |
|---|---|
| 입력 즉시 최고 속도, 정지 즉시 속도 0 | 짧은 가속·감속 적용. 최고 속도에서 정지까지 계산상 60ms |
| 이동 중 즉시 좌우 반전 | 먼저 감속하고 실제 이동 방향이 바뀔 때 인물 반전 |
| 화면 갱신 간격이 길어지면 이동 거리 감소 | 실제 갱신 시각의 차이로 이동량 계산. 긴 비활성 구간은 초기화 |
| 인물과 카메라가 매번 같은 양만큼 움직임 | 시간 기준으로 부드럽게 추적하고 진행 방향 여유 공간도 점진적으로 변경 |
| 이동 버튼의 단발 실행이 60만큼 즉시 이동 | 짧은 실제 이동으로 바꿔 보행·가감속·거리 판정을 공유 |
| 보행 순서 끝에 앞선 자세가 반복 삽입됨 | 제공된 5개 보행 자세를 순서대로 사용하고 거리당 주기 조정 |
| 하단 안내가 보행 영역에 모임 | 안전조치 안내를 위쪽으로, 조작 안내를 바닥선 아래로 이동 |
| 움직임 줄이기에서 정지 자세로 미끄러짐 | 이동에 필요한 보행은 유지하고 카메라의 추가 추적 효과를 생략 |

## 확인 결과

- 공개 판정 검사 6개와 이동 검사 4개, 합계 10개 통과.
- 이동 계산은 초당 30·60·120회 갱신에서 동일한 입력의 최종 거리 차이가 0.001 미만이다.
- 출발·정지·반전·짧은 입력을 1280×800 화면에서 녹화했다. `before-trace.json`과 `after-trace.json`은 입력 시각, 위치, 카메라, 자세, 좌우 방향을 담는다.
- 최종 녹화에서는 반전 입력 후 약 80ms에 반대 방향이 나타났다. 브라우저 표본 간격이 일정하지 않아 이 수치를 기기 공통 보장으로 보지 않는다.
- 왼쪽 위치 76과 오른쪽 3124에서 입력을 유지해도 위치가 변하지 않았다. 오른쪽은 움직임 줄이기를 켠 상태에서도 확인했다.
- 조사창을 연 상태에서 이동 입력을 해도 위치가 유지됐다. 창 비활성화는 blur 이벤트로 입력·속도 초기화를 확인했다.
- 공장 왕복에서 위치 2680 유지, 카메라 위치 차이는 0.001 미만이었다.
- 직접 이동으로 차단·잠금·표지, 잔류 에너지 조치·확인, 점검구 진입 후 성공했다. 판단 시도 1, 되감기 0. 재연습 시 시작 위치 704로 초기화됐다.
- 단발 이동 버튼은 시작 704, 누른 뒤 100ms에서 724, 정지 후 773으로 연속 이동했다.

## 남은 이미지 한계

제공 시트는 완전한 보행 주기가 아니다. 지지발이 땅에 붙은 채 몸이 지나가는 연속 자세와 출발·정지·회전 전이 자세가 부족하다. 화면의 도약감과 발 미끄러짐이 남아 있으며, 부츠 길이 10% 이하 미끄러짐 및 신체 높이 1% 이하 접지 오차는 충족했다고 판정하지 않았다. 가려진 발은 측정하지 않았다.

이를 더 개선하려면 동일 인물·시점·광원의 연속 보행 시트와 전이 자세가 필요하다. 이번에는 이미지를 새로 생성하거나 인물을 늘이고 압축하지 않았다. 배경에 이미 있는 먼지·빛·난간에 효과를 추가하지 않았다. 실제 운영체제의 창 전환 및 다른 브라우저는 별도 검증하지 않았다.
