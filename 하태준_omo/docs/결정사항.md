# SAFEPLAY 독립 구현 결정사항

기준 문서는 [구현계획](../구현계획.md), [PRD](../PRD.md), [독립 계약](contract.md)이다. 사용자 지정 작업 루트는 `하태준_omo`이며 이전 담당자와 경로 규칙보다 우선한다. 공용 코드·문서·자산과 기존 독립 후보를 변경하지 않는다.

## 시나리오와 판정

플레이어는 정지한 컨베이어 점검구의 이물질을 제거하는 작업자다. 점검구 밖에서 시작해 직접 차단, 본인 잠금, 표지, 잔류 에너지 조치, 차단 확인을 수행한다. 조사 기록은 실제 안전 상태를 대신하지 않는다. 원고의 운전원용 식별자는 재사용하지 않는다.

현장 절차가 승인되기 전까지 차단 지점과 조작은 게임용 예시다. 설비별 잔류 에너지 위험이나 실제 절차를 추정해 확정하지 않는다. 이 불확실성이 공개 상태와 판정 계약을 바꾸지 않는다. 사고는 실제 차단 또는 유효 잠금이 없는 상태로 진입했을 때만 재현한다. 표지나 확인 생략 자체를 벨트 가동 원인으로 묘사하지 않는다.

## 상태와 이동

`src/app.js`가 한 판, 화면, 활성 대상을 단독 소유한다. 현장과 패널은 콜백(callback)으로 요청만 보낸다. 앱은 현재 화면, 일시 정지 상태, 대상별 허용 행동, 현재 위치의 수평 거리를 다시 검사한다. 패널에서 전달한 거리나 오래된 조회 결과는 신뢰하지 않는다.

장애물이 없는 한 개의 수평 보행선만 사용한다. 대상별 정지점 `standX`와 상호작용 반경은 배치 모듈에서 관리한다. 대상 이미지의 높이와 원근상 중심은 거리 판정에 사용하지 않는다. 자유로운 상하 이동과 경로 탐색은 범위 밖이다.

사고 되감기는 기록을 유지하고 진입 전 안전한 위치로 돌아간다. 공장 복귀와 이어하기는 판과 위치를 유지한다. 다시 연습만 새 판과 위치·입력·카메라·패널·타이머를 초기화한다. 완료 판은 공장 재진입 때 결과로 복원한다.

## 고정 설명과 외부 연결 제외

외부 AI(인공지능), 서버 판정, 로그인, 점수 저장은 제외한다. [시나리오 원고](../../docs/시나리오.md)의 134행에 있는 AI 보충 설명은 PRD의 고정 설명 결정(23, 65, 146행)보다 오래된 제안이므로 구현하지 않는다. `기본 설명 사용`도 그 제안의 실패 대체 문구이므로 제외한다. 결과는 계약에 적힌 고정 이유와 설명을 항상 사용하며 출처 라벨이나 생성 중 문구를 표시하지 않는다.

## 자산과 완료 기준

[전체 공장 전경](../../assets/images/overview/factory-overview.png)은 검수 후보이며 읽기 전용으로 참조한다. [시작 장면](../../assets/images/scenario-scenes/01-start.png), [차단 장면](../../assets/images/scenario-scenes/02-isolate.png), [잠금·표지 장면](../../assets/images/scenario-scenes/03-lock-tag.png), [작업 전 확인](../../assets/images/scenario-scenes/04-check-before-entry.png), [안전한 이물질 제거](../../assets/images/scenario-scenes/05-safe-cleanup.png)는 구도와 확대 화면의 참고 자료다.

자산 검수 전에는 기능 검증용 임시 도형을 사용한다. 파일이 존재한다는 이유로 적격 자산으로 간주하지 않는다. 인물 없는 이동 배경, 투명 인물, 실제 보행 동작, 광원과 크기, 발 접촉, 방향 전환과 카메라를 순서대로 검증한다. 인물이 포함된 배경에 이동 인물을 중복 합성하지 않는다. 정지 캐릭터 시트를 보행으로 간주하지 않는다.

자산이 없거나 탈락해도 이미지를 생성하지 않는다. 새 이미지 생성은 이번 구현의 승인 범위 밖이다. 적격 이동 배경이나 보행 자산이 확보되지 않으면 기능 검증 결과와 별개로 자산 기반 시각 완료를 보류한다. 임시 도형이나 정지 인물로 시각 검증을 통과했다고 선언하지 않는다.

## 계약 보완 결정

공개 상수는 `TARGETS`, `ACTIONS`, `SAFETY_STEPS`, `TEXT`로 통일한다. 안전조치 목록의 키는 실제 `safety` 필드를 사용하며 잠금과 확인은 문자열 값까지 비교한다. 조사의 반환 설명은 동결하며 조사로 안전 상태를 바꾸지 않는다.

확인 실패와 진입 실패는 별개의 제출이다. 차단 확인 행동 실패는 확인 결과만 기록한다. 그 상태에서 작업 진입을 실제 제출하면 판단 시도를 한 번 늘리고 확인 실패 안내를 표시한다. 같은 안전 상태를 반복 적용하면 확인을 무효화하지 않는다. 잠금 보완은 표지와 잔류 에너지 조치를 보존하고 재확인을 요구한다.

문서 작성 단계에는 생산 코드를 추가하지 않는다. 계약의 식별자 수, 오류 정의, 우선순위, 링크와 금지 문구 경계를 검사하고, 규칙 구현 단계에서 공개 계약 검사로 이어간다.
