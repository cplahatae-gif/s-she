# 오답 피드백과 후속 상황 검증

검증일: 2026-10-09. 대상: `권기봉/초안`, Chrome 데스크톱. 1280×720, 1024×576 큰 글씨와 마지막 실제 브라우저 크기 1715×875에서 확인했다. 루트가 직접 조작한 브라우저 관찰과 자동 검사를 구분해 기록한다.

**현재 상태: 해당 요청의 최종 브라우저 검증 통과.** 혼합 실습의 완료·재생 취소·재진입, 최신 코드의 동료 기동과 되감기, 잠금 주인의 실제 접촉과 확대 상태 위험 표시를 확인했다. 브라우저에서 직접 실행한 오답의 범위는 아래 표에 한정한다. 상세 근거는 [관찰 데이터](observations.json), 대표 최종 화면은 [짧은 오답 안내](11-final-short-feedback.png)다.

## 변경한 표현

18개 오답 ID 각각에 짧은 제목과 **잘못된 점 / 위험 / 다음 행동**을 대응시켰다. 긴 설명은 처음부터 펼치지 않고 자세한 설명에서 볼 수 있게 했다. 사고와 보완 안내를 구분하며 모든 오답을 같은 사고로 처리하지 않는다.

행동 다시 보기는 같은 선택의 현장 연출만 재생한다. 새 선택을 판정하거나 학습 이벤트를 추가하지 않는다. 타인 잠금에 의존한 상황에서는 잠금 주인이 돌아오는 후속 예시를, 표지의 문제에는 동료의 표지 확인을, 기동 요청에는 오퍼레이터의 응답을 연결한다.

## 직접 확인한 오답과 후속 상황

| 선택 | 루트가 직접 관찰한 결과 | 통계·상태 확인 |
|---|---|---|
| 운전 중 진입 | 사고 뒤 짧은 세 항목 안내와 접힌 자세한 설명을 확인했다. 자세한 설명과 행동 다시 보기를 조작했다. | 재생 전후 행동 선택 1회·되감기 0회 유지 |
| 연락 없이 정지한 벨트에 접근 | 최신 코드로 새로 불러온 실습에서 동료가 실제 초록 기동 버튼에 손을 대고 벨트가 다시 움직이는 사고를 확인했다. | 기동 접촉 시 벨트 정지 → 접촉 후 벨트 운전. 사고 뒤 되감기하면 정지 상태 복원, 선택 2회·되감기 1회 |
| 타인 잠금에 의존 | 수강생은 위험 구역 밖에서 지켜봤다. 김 작업자가 해당 자물쇠에 실제로 손을 대고 자기 잠금을 해제했다. | 해제 뒤 잠금 없음·차단 ON·벨트 정지. 일반 보완 안내이며 기동 사고로 바꾸지 않음. 재생 뒤 선택 3회 유지 |
| 표지 생략 | 동료가 작업 표지를 확인하고 식별 누락을 표시했다. | `missing-tag`; 본인 잠금·차단 OFF·벨트 정지 유지 |
| 다른 이름의 표지 | 동료가 표지를 확인하고 작업자 불일치를 표시했다. | `owner-mismatch`; 본인 잠금·차단 OFF·벨트 정지 유지 |
| 시험 중 움직임을 확인 완료로 처리 | 차단 이상을 발견한 뒤 작업 진입 전에 정지·보완 안내로 이어졌다. | 접근을 완료하지 않고 보류 |
| 제거 준비 중 기동 요청 | 오퍼레이터가 요청을 보류하는 응답을 보여줬다. | 본인 잠금·표지·벨트 정지 유지 |

이 표는 **직접 실행한 일부 오답**의 기록이다. 18개 오답을 모두 브라우저에서 직접 검증했다고 주장하지 않는다. 24개 선택의 행동 대응과 18개 짧은 피드백의 누락·대응 관계는 자동 검사로 별도 확인했다.

타인 잠금 예시는 수강생이 남의 자물쇠를 해제하는 장면이 아니다. 해당 잠금의 주인이 자신의 잠금을 해제해 본인 잠금이 없는 수강생의 보호가 유지되지 않을 수 있음을 보여준다. 잠금 해제만으로 곧바로 벨트가 기동했다고 표현하지 않는다.

## 작은 화면과 큰 글씨

1024×576에 큰 글씨를 적용했을 때 본문은 18px이었다. 초기 확인에서는 고정된 하단 버튼의 아래 약 11px가 잘리는 문제를 발견했다. 하단 위치를 `bottom: 0`으로 수정한 뒤 재확인했고, 버튼의 아래 경계 **557.33px**가 패널 아래 경계 **560px** 안에 놓였다. [수정 후 큰 글씨 화면](06-large-small-fixed.png)을 최종 배치 근거로 사용한다. `02-large-small.png`는 수정 전 관찰 자료다.

확대 연출 중 왼쪽 위험 표시가 잘리는 문제도 발견해 확대값의 역수를 적용하는 방식으로 수정했다. 최신 코드를 새로 불러온 뒤 카메라 확대값 **1.18**에서 `위험 예시` 표시의 전체 글자가 보이는 것을 루트가 직접 확인했다. 김 작업자가 자신의 잠금에 손을 댄 실제 장면과 함께 [최종 잠금 접촉](10-final-owner-contact.png)에 남겼다. 근거는 `final-owner-contact-with-readable-risk-badge`다.

## 재생·취소·왕복·완료

제거 단계의 기동 요청 오답에서 행동 다시 보기를 실행하고, 지도 이동으로 재생을 취소한 뒤 B/C에 재진입했다. 재진입 후에도 행동 선택 **10회·되감기 0회**였으며 같은 오답 결과로 돌아왔다. 마지막 정답 후 완료 결과는 행동 선택 **11회·되감기 0회**, 첫 선택 완료 **2 / 6**, 보완 단계 **4개**였다.

완료 분석에 MCC 잠금 오답 1회, 표지 오답 2회, 트라이아웃 오답 1회, 제거 작업 오답 1회의 근거가 남았다. 연출 재생을 새 선택으로 중복 기록하지 않았다. 근거는 `cleanup-resume-same-count`, `complete-eleven-choices-no-replay-history`와 [혼합 실습 완료](08-complete-mixed-run.png)다. 이 이미지는 최종 위험 표시의 확대값 보정 이전 자료이며, 학습 횟수와 오답 근거 확인에 사용한다.

최신 코드의 별도 새 실습에서는 [동료의 기동 버튼 접촉](09-coworker-start-contact.png)을 확인한 뒤 사고에서 되감기했다. `final-rewind-restores-checkpoint`에서 벨트 정지, 조작반의 정지 상태와 선택 2회·되감기 1회를 확인했다. 그 후 연락 정답과 타인 잠금 오답을 이어서 실행했다. `final-owner-release-short-result`는 김 작업자의 해제 완료 뒤 잠금 없음·차단 ON·벨트 정지, 부상 없는 일반 안내이며 선택 4회·되감기 1회다. 이 별도 실습의 횟수는 완료한 혼합 실습의 11회 기록과 합산하지 않는다.

마지막 실제 브라우저 크기 1715×875에서 [최종 짧은 안내](11-final-short-feedback.png)의 세 항목, 접힌 자세한 설명, 행동 다시 보기 버튼과 위험 예시 표시를 확인했다. 최신 브라우저 경고·오류 로그는 빈 배열이었다.
